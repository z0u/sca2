# Baseline comparisons for SCA — plan and related-work delta

A 2026-08-13 four-angle literature sweep (gradient-routing lineage, training-time interpretability, unlearning, post-hoc erasure/steering) is banked in [`references/related-work-delta-2026.md`](/references/related-work-delta-2026.md), including which entries are snippet-only and need verification before citing. Headlines: SGTM is now its own paper (arXiv:2512.05648) and is the must-run training-time baseline; post-hoc bounded-side-effect methods now exist (COAST, arXiv:2605.01167; pre-intervention prediction, arXiv:2606.08365), so SCA's bound should be framed as by-construction rather than merely bounded; 2025 auditing standards (relearning rebound, activation-perturbation, minor-direction recoverability) should be adopted in our evals. Prep task: keep the eval contract method-agnostic — every baseline produces (model, subspace, intervention operator) and the shared eval scores the triple. Sequencing sketch: post-hoc tier (probe / diff-in-means / LEACE on existing controls) + filtered-corpus row first; SGTM as its own preregistered experiment; RMU-family row at D2.3; one bounded SAE experiment with output-score feature selection (arXiv:2505.20063).

**2026-09-06, housekeeping** — the deadline the note above set has passed, and it was a decision rather than an oversight. What the slip has cost so far is small, and that is worth writing down before it stops being true. Ex-2.2.1's arms are post-hoc interventions on D2.1 checkpoints, so re-scoring them under a row added later is an eval pass over stored weights rather than a retrain. The two experiments after it in the plan — anchor operation, suppress operation — train, and a row added once those arms exist is re-scoring with a training bill behind it. So the argument for declaring early is stronger now than when it was written, and the trigger to read this against is the next prereg rather than ex-2.2.1.

One thing to settle as part of declaring, since the design already hedges with "where portable": which of the three this testbed can carry. Relearning rebound wants a fine-tuning budget the plan has not costed, while off-axis recoverability is close to ground `sca.compute.geometry` already covers — and [an off-axis probe R² does not bound an intervention](./off-axis-probe-r2-does-bound-intervention.md) is the methodology item saying what that number does and doesn't mean, so the row should be specified against it rather than beside it.

**2026-09-07, ex-2.2.2 prereg** — two pieces of the sweep reached the [ex-2.2.2](/docs/m2/ex-2.2.2/report.py) prereg. The sweep marks it tractable in a toy transformer, so a LUNAR row joins RMU in the design's D2.3 list. And the off-axis recoverability row (E3) is now specified against the [off-axis R² item](./off-axis-probe-r2-does-bound-intervention.md), with the raw-RGB floor beside it, rather than reported bare.
