# Restructure the D2.2 design doc

Review of the 2026-10-21 refresh (PR #277) found [the D2.2 design doc](/docs/m2/d2.2/design.md) hard to read overall, and asked for a significant restructure later, beyond the refresh. Likely causes: each claim section has grown by accretion, one paragraph per experiment, so the current state is spread through long Observations blocks with provenance mixed in; the setup is one long definition list; and "What comes next" repeats material from the claims. A restructure might lead each claim with where it stands in a sentence or two, move the history to the index or a details block, and keep the next steps short with links into the backlog.
